# SOBI'S MULTIVERSE
## MASTER MVP REDESIGN PROMPT

We already have the multiverse skeleton and we have now selected the background/visual environment for each universe.

Your task is to completely redesign the **UI, information architecture, content presentation, spacing, and interactions inside each universe** so that each one feels intentionally designed for its specific background.

We are NOT replacing the backgrounds.

We are NOT turning all universes into variations of the same dashboard.

We are NOT trying to connect the universes with cinematic transitions yet.

The goal of this pass is:

> **Make every universe independently complete, visually distinct, content-rich, readable, responsive, and capable of standing alone.**

The backgrounds are already chosen.

Now the UI must learn how to live inside them.

---

# 1. CRITICAL DESIGN RULE

DO NOT think of these as eight sections of one website.

Think of them as:

**eight independent digital worlds.**

Each universe must have:

- its own composition
- its own UI language
- its own information hierarchy
- its own density
- its own interaction patterns
- its own way of presenting content
- its own responsive behavior

Shared components are allowed only at the low-level infrastructure level.

Do NOT create one universal:

`Section`
`Card`
`Header`
`Grid`
`Dashboard`
`Tabs`

system and reuse it everywhere.

That is exactly what is making the current prototype feel generic.

A Project UI in Builder does not need to look anything like a Research UI.

Arsenal should not look like Builder.

Journey should not look like Research.

About should not look like a dashboard at all.

---

# 2. BACKGROUNDS ARE SACRED

The existing backgrounds have already been intentionally selected.

DO NOT replace them.

DO NOT redesign them.

DO NOT hide them underneath giant opaque containers.

DO NOT place a giant solid panel across the center of the screen that destroys the composition.

Treat each background as a major visual asset that the UI must compose around.

The background should remain clearly visible throughout the experience.

You may use:

- transparent surfaces
- translucent panels
- local blur
- subtle readability gradients
- small contrast masks
- soft shadows
- thin borders

where genuinely necessary.

But the background must still feel present.

The rule is:

**UI sits inside the universe. UI does not cover the universe.**

---

# 3. CONTENT MUST BE REAL

Remove placeholder/fabricated portfolio content.

Populate the universes using the real information available from `sobi.codes`.

The current public portfolio describes Sobi as an AI/ML-focused developer and researcher working around applied AI, document intelligence, generative AI, NLP, behavior-aware interfaces, and creative tooling. It also lists programming languages, AI/ML capabilities, application-development tooling, systems/tooling, projects, recognition, achievements, and public links.

Do not fabricate project metrics, paper titles, awards, dates, clients, users, performance numbers, or technical claims.

Where information is unavailable, present the information without inventing specifics.

# 13. RESPONSIVE BEHAVIOR

Every universe must be independently responsive.

Do not simply stack the desktop dashboard vertically on mobile.

Each universe should have its own mobile composition.

The background must remain meaningful.

Content must never:

- overflow horizontally
- collide with the background in unreadable ways
- extend outside the universe container
- become hidden below fixed navigation
- create giant empty blocks because desktop dimensions were preserved

Use responsive typography and spacing.

Prioritize the visual identity of each universe over preserving the exact desktop layout.

---

# 14. CONTENT + BACKGROUND COMPOSITION RULES

For every universe ask:

1. Where is the background visually strongest?
2. Where is the natural empty space?
3. Where should information live without covering that area?
4. What interaction metaphor matches the background?
5. What is the minimum information necessary?
6. What can be revealed only after interaction?
7. What should remain visible at all times?

The answer must differ from universe to universe.

Do not center everything.

Do not make every page symmetrical.

Do not use the same content width everywhere.

Do not use the same panel style everywhere.

Do not use the same card radius everywhere.

Do not use the same typography treatment everywhere.

---

# 15. OVERFLOW / CONTAINER RULE

Every universe owns its own scene.

Conceptually:

Universe
├── Background
├── Ambient layer
├── Universe UI
├── Universe content
└── Local controls

The background must be clipped to the universe.

Content must remain inside a deliberate content-safe region.

Use proper max-widths, viewport calculations and responsive spacing.

If a universe needs more vertical space than one viewport, allow that universe to grow naturally.

Do NOT force everything into 100vh if that causes text to overflow.

The goal is not "fit everything on screen".

The goal is:

**make the universe feel intentionally composed at every size.**
