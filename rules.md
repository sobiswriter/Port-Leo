# Project working rules

- Preserve the background engines and make their variations accessible.
- Prioritize a sense of place, readability, and meaningful interaction over decorative controls.
- Each room owns its layout. Share navigation and environmental infrastructure, not a universal portfolio card template.
- Keep all existing portfolio records accessible. Do not invent accomplishments, metrics, dates, or project-specific URLs.
- Label static experiment outputs as illustrative. Never imply a message was sent when only an email draft was opened.
- Maintain URL hashes, browser history, semantic controls, visible focus, mobile flow, and reduced-motion support.
- Do not publish, commit, or rewrite Git history as part of an ordinary local design iteration.
- Update memory.md with actual implementation and validation outcomes. Record limitations honestly.
